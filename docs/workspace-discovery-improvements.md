# Workspace discovery and supplier portal improvements

## Delivered scope

- `Work/Tasks`: role-specific, database-derived work queues; no task entity, assignment, new status or automatic transition. Requester drafts/returns; officer review excluding self/own department, conversions, draft/published tenders, elapsed open deadlines, closed-offer review and responsible final-stage management; appointed manager report review and non-self-configured criteria; assigned evaluation/final-decision work; supplier invitations and editable drafts; Admin supplier applications. Evaluation/final-stage entries are workspaces to review, not assertions that every prerequisite or a vote remains outstanding. Existing destination services decide every action. Notifications/eligible clarification/message inboxes remain directly accessible.
- `Work/Search`: parameterized, paginated search over authorized database records, not only dashboard rows. Personal requester ownership, current committee membership and stage restrictions, supplier-only participation and Admin confidentiality take precedence. Category summaries show six rows; category pages show twenty. Counts refer to work records across categories, not distinct tenders.
- `SupplierPortal/Details/{tenderId}`: a supplier-owned invitation, authoritative tender items, terms, dates, own offer/documents and existing bid/response/summary links. No new document workflow, competitor details or mutations on portal reads. Existing response POST, antiforgery/version checks and bid/private-copy services remain authoritative. A stored pending invitation outside its response period is shown with a closed-period notice; existing invitation workflow owns persistent expiry.
- `Work/Audit`: fresh Admin eligibility plus a restrictive SQL projection of existing requisition, tender, department, employee and supplier-profile metadata. Excludes confidential record types, all audit reasons/payloads, actor identities and status payloads. No audit rows are generated by viewing it. This is intentionally not an unrestricted audit dump.
- `Notifications/Menu` and `Notifications/Watch`: same-origin authenticated MVC HTML partial and native server-sent events. Signals contain no notification text. Reads see committed SQL records; no SaveChanges interceptor or pre-transaction-commit push is used. Account eligibility is rechecked each cycle. Up to two streams per account per application instance; cancellation releases leases. Stream checks at fifteen-second intervals, rotates after approximately seventy-five seconds, and reconnects; browsers/proxies without streaming fall back to thirty-second visible-page refresh. Hidden pages disconnect. Background replacement preserves keyboard focus; explicit mark-read still uses existing antiforgery POST.

## Security and compatibility

No schema, migrations, production/test SQL writes, packages, new roles or procurement transitions. Existing MVC routes remain working. All newly generated destination routes are server-selected. Search is bounded to 160 characters; dates/page sizes are validated/bounded. No-store responses and Razor encoding remain in place. Normal authorization still protects every linked record and download even after search or task results become stale.

UI reuses the existing ivory/navy/gold design system, responsive tables, focus states and reduced-motion conventions. 21st catalog metadata was consulted for task-list organization; no component code was copied or installed. Existing 21st CLI is unavailable, so no CLI review is claimed. The user-selected STMS workflow remains authoritative over Orange examples.

## Verification

`--work-hub-checks-only` performs real SQL Server query translation without connections, role/scope/redaction and connection-lease checks, plus compiled Razor/HTTP tests using in-memory services. It verifies supplier isolation, draft/submitted controls, original response antiforgery wiring, search/filter binding, safe metadata, notification owner isolation, live-change delivery and account revocation. Memory MVC fixtures do not prove production SQL query results or load capacity.

The fixed database-free safe-acceptance allowlist includes the new suite. The existing 24 safe suites passed during this change, including schema model, Identity/employees/departments, bids/documents, committee workflows, reports, contact/inbox, passkeys, voice, AI/extraction and personalized copies. No optional SQL/device/model acceptance is implied.

Edge/Playwright checks cover tasks/search/audit and supplier portal at 1440, 768, 390 and 320 pixels; no page-level overflow after the narrow-header correction. JavaScript reported no page errors; mark-read updated the badge without leaving the page. Mobile drawer and notification keyboard closing were checked. Table overflow stays inside its keyboard-focusable region. QA screenshots/logs remain outside the repository and use synthetic memory fixtures.
