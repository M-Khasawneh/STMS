# Supplier registration and Admin review

## Implementation

Reuses the existing Identity, SupplierProfile and SupplierDocument entities, existing Supplier/Admin roles and MVC conventions. Public registration at /Suppliers/Register collects company name, registration/tax numbers, contact name/email/phone, username/password/confirmation and exactly three required documents. Numbers are trimmed and uppercased for storage and comparisons. New users are created through UserManager with only the existing Supplier role and a Pending profile. A generic confirmation page exposes no identifying details. No supplier is automatically signed in.

Files: Company Registration Certificate, Business / Trade License and Tax Registration Certificate. PDF, JPG, PNG only, nonempty, up to 5 MiB each. Extensions and magic bytes must agree; PDF EOF and JPEG end markers are checked as well. Client validation provides early feedback; the server bounds actual reads and rejects invalid content. No scanning libraries or executable upload handling were introduced. Private files use cryptographically random references in App_Data/SupplierDocuments outside wwwroot, not uploaded names. Download responses are authorized attachments with nosniff and restrictive CSP. File signatures are format checks, not malware scanning or full document parsing.

Registration uses one transaction for Identity user/role, profile and document records. Storage occurs before commit; failures roll back SQL and compensate saved files. Failure to remove a file is logged with only its private reference. A process/machine crash during filesystem/SQL coordination can leave unreferenced private files; it cannot expose them through the download action, which requires a database record and authorization. There is no cross-resource distributed transaction.

Admin pages at /Suppliers and /Suppliers/Details/{id} show company/contact information, current status, official downloads and review controls. Pending applications may be approved or rejected; Approved suppliers may be suspended. Rejection/suspension require a reason, limited to 2000 characters. Status, reason, reviewer ID and UTC time persist. Serializable review locks and expected-status comparison reject stale decisions. No reactivation/resubmission workflow was added.

Approved supplier-only accounts may use the existing Login and Logout and view /Suppliers/Status plus their own documents. Pending, Rejected and Suspended suppliers cannot sign in. The existing per-request cookie validation rechecks eligibility, and review changes rotate the security stamp. Default employee policies still require employee roles; supplier approval grants no employee or Admin access. Mixed Supplier/employee role accounts remain ineligible. Supplier document queries enforce owner and Approved status; competitor documents return 404. Admin reviews use the existing Admin policy and global antiforgery protection.

## Database deployment completed

Read-only preflight: SourcingTenderDB has zero supplier profiles/documents, only existing admin with Admin role, no supplier duplicates, two prior migrations. Existing supplier foreign keys and nonunique UserId index were inspected.

New migration: 20261113120000_SupplierRegistrationUniqueness. It replaces the nonunique UserId index with a unique index and adds unique RegistrationNumber and TaxNumber indexes. No tables, entities, columns, roles or existing data are recreated. Existing migrations and the Word requirements are unchanged. Unique indexes provide race-safe enforcement even when concurrent requests pass the preliminary duplicate query. Migration target model/snapshot updated; schema check confirms no pending model changes.

Reviewed SQL: docs/supplier-registration-migration.sql. Request approval before applying with sqlcmd -S localhost\MSSQLSERVER02 -d SourcingTenderDB -E -C -b -i docs/supplier-registration-migration.sql. Registration refuses writes until this migration appears in history. After explicit user approval, the migration was applied successfully and the transient SQL tests passed. Final SQL verification confirms all three unique indexes, three migration-history entries, zero remaining supplier profiles/documents, and the original admin -> Administration -> Admin assignment with no invalid foreign keys.
