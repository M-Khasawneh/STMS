# Employee departments and Identity roles

Each employee has one required department, stored in EmployeeDepartments with UserId as its primary key and non-null foreign keys to the existing Identity user and Department. Employee creation and edits save the department and Identity roles atomically. Non-employee accounts do not require assignments. The sign-in eligibility check requires an employee department assignment.

Create and Edit provide department selection and multiple employee-role selection. Supplier is excluded and rejected server-side. Editing roles requires explicitly checking Change role assignments; other edits preserve all existing memberships. The first admin account cannot lose Admin or be disabled. Department assignment does not scope Admin authorization; existing system-wide role policies are unchanged. Committee membership remains scoped to its Tender.
